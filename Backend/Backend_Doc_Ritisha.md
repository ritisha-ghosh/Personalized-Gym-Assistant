Chapter 3.4: Database Design
3.4.1 Overview
The application utilizes MongoDB, a NoSQL document-oriented database, to handle the flexible nature of user data and AI-generated plans. This choice allows for rapid iteration of schema structures, particularly for nested workout routines and nutritional data.

3.4.2 Database Architecture
The database is composed of four primary collections: Users, WorkoutPlans, DietPlans, and ProgressLogs. Relationships are maintained via MongoDB ObjectId references, creating a relational structure within the document store.

3.4.3 Schema Definitions
1. User Collection
The core entity storing authentication credentials, physical attributes, and personalization constraints.

Collection Name: users

Key Fields:

_id: ObjectId (Primary Key)

name: String

email: String (Unique, Indexed)

password: String (Hashed)

profile: Object

age: Number

gender: String (Enum: 'Male', 'Female', 'Other')

height: Number (cm)

weight: Number (kg)

activityLevel: String (e.g., 'Sedentary', 'Active')

goals: Object

primaryGoal: String (e.g., 'Muscle Gain', 'Weight Loss')

targetWeight: Number

medicalConditions: Array[String] (e.g., 'Knee Injury')

createdAt: Date

2. Workout Plan Collection
Stores the personalized workout routines generated by the AI or assigned by the system.

Collection Name: workoutplans

Key Fields:

_id: ObjectId

userId: ObjectId (Ref: users)

generatedAt: Date

status: String (Enum: 'Active', 'Archived')

schedule: Array[Object]

day: String (e.g., 'Monday')

focus: String (e.g., 'Upper Body')

exercises: Array[Object]

name: String

sets: Number

reps: String (e.g., '8-12')

restPeriod: Number (seconds)

3. Diet Plan Collection
Stores nutritional guidelines and meal plans tailored to the user's caloric needs.

Collection Name: dietplans

Key Fields:

_id: ObjectId

userId: ObjectId (Ref: users)

dailyCaloricTarget: Number

macros: Object

protein: Number (g)

carbs: Number (g)

fats: Number (g)

meals: Array[Object]

type: String (e.g., 'Breakfast', 'Lunch')

suggestions: Array[String]

calories: Number

4. Progress Log Collection
Tracks the user's daily activities, weight changes, and workout completions to feed back into the AI model.

Collection Name: progresslogs

Key Fields:

_id: ObjectId

userId: ObjectId (Ref: users)

date: Date

weightLogged: Number

workoutsCompleted: Boolean

caloriesConsumed: Number

notes: String

3.4.5 Indexing Strategy
To optimize query performance, the following indexes are applied:

Users: unique index on email.

WorkoutPlans: compound index on userId and status to quickly retrieve the user's active plan.

ProgressLogs: index on userId and date to efficiently query history and visualize progress trends.
